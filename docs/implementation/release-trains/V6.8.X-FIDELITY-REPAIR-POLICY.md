# V6.8.x — Fidelity repair policy

**Applies after:** first `6.8.0` publication attempt or when fidelity regressions appear during 6.8 train.
**Authority:** [V6.8.0-EXECUTION-PLAN.md](./V6.8.0-EXECUTION-PLAN.md)

## Allowed 6.8.x patches

- Lifecycle / completion correctness
- Parent reconciliation bugs
- Callback-reuse isolation failures
- Tool-identity regressions
- Persist-by-intent bugs
- Documentation and fixture repairs for the fidelity contract
- Compatibility with upstream LangChain/LangGraph within existing peer ranges

## Prohibited without new minor authorization

- New product surfaces unrelated to fidelity
- Schema breaks
- New public packages
- Default network / upload behavior
- v7 scope

## Process

1. Classify regression against fidelity contract.
2. Add failing fixture/test first.
3. One commit-sized patch.
4. Full patch gate + pack:smoke.
5. Changeset **patch** only when publishing a repair release.

## Historical note

Prior adoption freeze docs (`V6.8.X-FEATURE-FREEZE.md`, `V6.8.X-FREEZE-ACTIVE.md`) described a pilot-blocked 6.8 publication under the old pre-v7 roadmap. That operational freeze is superseded by the Stability and Focus program; keep those files as history with pointers here.
